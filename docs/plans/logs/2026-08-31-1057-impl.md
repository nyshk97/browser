## P1
- `src/renderer/components/UrlEdit.tsx:UrlEdit` — 入力欄の `maxLength={4096}` は**長い URL の貼り付けを黙って切り詰める**。Chromium は maxlength を超えるペーストを切って入れるので、4096 字超の URL を貼ると `isHttpUrl` も `normalizeStoredUrl` も通り、**途中で切れた別の URL がそのまま保存される**（エラーも出ない）。コメントが避けたかった「文言が『重複』に化ける」より悪い。`maxLength` を外し、`submit` で `text.length > 4096` を専用の文言（例「URL が長すぎます」）で弾く形にする。
- `src/main/registry.ts:updatePinnedUrlFromTab` — `setDefinitionUrl` に host 変化時の `faviconUrl = null` を統合したことで、「このページに更新」で別 host のページに差し替えると**開いているタブに favicon があるのに定義が頭文字アバターに落ちる**。`setFaviconForDefinition` は `page-favicon-updated` 起点なので、そのタブを閉じて開き直すまで直らない（URL 編集と違い、ここは正しい favicon が手元にある）。`setDefinitionUrl` が true を返したら `if (tab.faviconUrl && !tab.window.isPrivate) setFaviconForDefinition(id, tab.faviconUrl, tab.url)` を続けて呼ぶ（`registry.ts:3176` と同じ形）。`updateFavoriteUrlFromTab` も同じ。
- `src/main/ipc.ts:registerIpcHandlers` — `nemo:update-pinned-url` の上のコメント「定義 ID は main 側でタブから導出する（renderer から無関係な定義を書き換えられる口を作らない）」が、3 行下の `nemo:set-definition-url` と真正面から食い違う。plan の Phase 2 でも「既存方針を明示的に緩めるのでコメントも更新する」と決めていて、そこだけ未反映。旧コメントを「このハンドラは key だけ受ける」に限定し、緩めた根拠は下の新コメントにある旨を一言添える。

## P2
