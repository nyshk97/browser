# kypr のパスキーを Nemo で作って使う（Nemo を WebAuthn の認証器にする）

## 概要・やりたいこと

kypr がパスキーの認証器になった（kypr 側の plan: `~/kypr/docs/plans/2026-09-30-1631-passkeys.md`。仕様は `~/kypr/docs/crypto-spec.md`「パスキー」「パスキー（`passkeys`）」）。パスキーの秘密鍵はログインの `passkeys` に入って同期され、iOS の自動入力の拡張機能からも作れる・使える。

今の Nemo はパスキーを求めるサイトに入れない（Electron 41 は Touch ID の認証器を持たず、`webauthn-shim.js` は宙吊りを防ぐために NotAllowedError を先に返しているだけ。Bitwarden の拡張が代わりに答えていたが 2026-09-28 に外した）。証券会社を中心にログインでのパスキーの必須化が進んでいる（SBI 証券は 2026-06-30 から「原則必須」）。

**この plan は Nemo 側**で、Nemo を kypr のパスキーの認証器にする。ページの `navigator.credentials.create` / `get` を main に回し、kypr の保管庫の鍵で登録・署名する。最初の目標は **SBI 証券のパスキーを Nemo から作ってログインでき、同じパスキーで iPhone からもログインできる**こと。

## 前提・わかっていること

### kypr で決まったこと（Nemo に関わるもの）

| 論点 | 決定 |
| --- | --- |
| データの形 | ログインの `passkeys`（`credentialId` / `rpId` / `userHandle` / `userName` / `userDisplayName` / `rpName` / `privateKey`（PKCS#8 の base64url）/ `alg`（-7）/ `counter`（0）/ `discoverable` / `createdAt`）。無ければ `[]`。要素の知らないキーは残す |
| 方式 | ES256 だけ（`pubKeyCredParams` に -7 が無ければ NotSupportedError）。counter は常に 0。attestation は `none`。AAGUID は 0。フラグは BE・BS を立てる |
| 本人確認 | **毎回 Touch ID**（UV を嘘なく立てる。パスワードの自動入力とは別）。Touch ID が使えなければ断る（NotAllowedError）。kypr がロック中なら解除を促し、Touch ID での解除はそのまま本人確認を兼ねる（2 回出さない） |
| 候補 | `allowCredentials` があればそれに載っていて rpId が一致するもの、空なら rpId が一致する全部。ゴミ箱のログインは除く。0 件なら NotAllowedError。2 件以上ならアカウントを選ばせてから Touch ID |
| `excludeCredentials` | 載っているパスキーを持っていれば InvalidStateError |
| 入れるログイン | rpId のドメインに合うログインで、ユーザー名が `user.name` と一致するものが 1 件だけならそこに足す。そうでなく合うログインがあれば、それらと「新しいログイン」から選ばせる。無ければ新しいログイン。書けなければ（オフライン・読み取り専用）断る。409 なら差分を読み直して 1 回だけやり直す |
| rpId の検証 | **main で行う**（origin はページの申告を信用せず frame の URL から取る）。https（http は localhost だけ）・rpId は origin のホストかその親ドメインで公開接尾辞でない |
| パスキーだけのログイン | パスワードが空でパスキーを持つログインは、パスワードの自動入力の候補に出さない（`matchingLogins` が弾く） |
| PRF | 対応しない。kypr の Web の origin から来た kypr の形の要求は、今までどおり `web-authenticator.ts` が先に受ける |
| conditional | v1 は `mediation: "conditional"`（ユーザー名欄の自動補完）を今までどおり素通し。後で足す |

### kypr 側にあるもの（vendoring でコピーされる）

- `crypto/item.ts`: `Passkey` 型・`LoginItem.passkeys?`・`loginPasskeys`。`crypto/encoding.ts`: `b64urlEncode` / `b64urlDecode`
- `client/passkey.ts`（新規）: `createPasskey`（要求 → 保管庫に入れる要素と attestationObject・SPKI の公開鍵）・`assertPasskey`（要素と **clientDataHash** → authenticatorData・DER の署名・userHandle）・`rpIdAllowed(origin, rpId)`・`passkeyCandidates` / `hasExcludedPasskey` / `passkeyTargets`（入れるログインの判定）・`withPasskey` / `newPasskeyLogin`。WebCrypto だけを使うので main の Node で動く
- `client/url-match.ts`: `matchingLogins` がパスキーだけのログインを弾く
- テストベクタ: `passkeyLoginItem` / `loginItemMalformed` / `passkeyAuthenticator` / `rpIdChecks`

### 調べてわかったこと（Nemo のコード。2026-09-30）

- `src/shared/webauthn-shim.js`: main world で `navigator.credentials.get` / `create` を包み、Electron で宙吊りになる要求を NotAllowedError で先に返す。isUVPAA は preload の時点の native の値（false）を握る。**サブフレームには配られない**（Electron の preload はトップフレームだけ）
- `src/shared/kypr-webauthn-shim.js` + `src/main/kypr/web-authenticator.ts`: kypr の Web の origin だけで PRF の要求に答える小さな認証器。ページの shim から IPC（`nemo:kypr-webauthn`）で main に回し、main で送り手（メインフレーム・kypr の origin・通常のページセッション・表示中のタブ）を確かめ、`touch-id.ts` の `promptTouchId` を通す。**同時の要求は断る**。同じ作りを広げられる
- kypr の保管庫のセッションと候補は `src/main/kypr/index.ts`（`matchingLogins` を使う候補・`summaryOf`）

## ログ
### 試したこと・わかったこと
- `@simplewebauthn/server` の署名の検証が `Cannot get schema for 'ECDSASigValue' target` で落ちた。本体が既存の `@peculiar/asn1-schema@2.9.4`（electron-builder 側）に寄せられ、`asn1-ecc` は 2.10.0 を読むのでスキーマの登録先が分かれていた。`pnpm update --depth Infinity` は `@electron/windows-sign` の fs-extra まで上げたので戻し、`pnpm.overrides` で asn1-schema を 2.10.0 に固定した
- 既存の verify-kypr の「kypr 以外の origin（`http://localhost`）では今までどおり」は、パスキーの認証器が localhost で答えるようになるので、パスキーも扱えない `http://foreign.localhost` に移した（意図は同じ）
- 「別の端末」の `other`（VaultSession）は 1 回目の起動の端末の登録の取り消しの検査でセッションが切れるので、パスキーの検査では開き直す
- 自走検証（2026-09-30）: `verify:only kypr` 149 件 PASS（パスキー 24 件）。対照として詳細の `passkeys` 削除と `kyprLoginForFill` の拒否を外すと、その 2 件だけ FAIL する

### 方針変更
- アカウントの選択は、ポップアップの流用でも専用のダイアログでもなく、既存のブラウザ UI のダイアログ（`prompts.ts`）に種類を足した（自走検証が DOM のボタンで答えられ、ウィンドウごとの順番待ちもある）
- Touch ID の重なり防止は 2 段にした: 要求のロック（`holdWebAuthnRequest`。PRF とパスキーで共通。選択から Touch ID まで握る）と、`promptTouchId` 自体が出している最中の 2 枚目を出さない見張り（自動入力の解除も含む）
- ロック中の get は、保管庫が読めないので「解除の Touch ID → 候補の選択」の順になる（解除が本人確認を兼ねるので Touch ID は 1 回）。候補が 0 件なら解除のあとで内側に渡す
- http の localhost 以外・IP アドレスの origin は、SecurityError でなく内側に渡す（kypr が扱えない origin で、今までの挙動を変えない）
