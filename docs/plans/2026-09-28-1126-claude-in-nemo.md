# Claude in Nemo（Claude Code から Nemo を操作する）

## 概要・やりたいこと

Chrome の Claude in Chrome（以下 CiC）と同じことを、Claude Code から Nemo で行えるようにする。
ブラウザ内のチャット欄は対象外（後から同じ仕組みに載せられるなら載せる）。

CiC の不満:
- Chrome を開いて拡張のサイドパネルを開かないと接続できない（Nemo は常時起動なので、Nemo 側に口を置けば起きない）
- 操作後にタブグループが残り、セッションごとに空グループが溜まる

やりたいこと:
- Claude の操作は **Nemo の新しいウィンドウ（エージェント窓）** で行う
- Claude が操作中も、**元の Nemo の窓は普通に手で使える**
- ログインや 2FA が要るところは**ユーザーがエージェント窓で手動操作**し、「ログイン終わったから続きをやって」で Claude が再開する

パスワードマネージャーは別途自作して Bitwarden から移行する予定がある。そのため**初版のエージェント窓には Bitwarden を載せず**、
「エージェント窓にパスワードを入れる口」だけを Nemo 側に用意して、自作のパスワードマネージャーを後で差し込む。

## 前提・わかっていること

### 決定事項

| 論点 | 決定 |
|---|---|
| 方式 | **Nemo の main に MCP サーバを内蔵**し、ページ操作は main の `webContents.debugger`（ページ単位の CDP）で行う（案 A） |
| Claude Code との接続 | **自作の stdio ブリッジ**（`.mjs`、`Nemo.app/Contents/Resources` に同梱、ユーザーの node で動かす）→ Nemo main の **unix socket** `<userData>/agent.sock`。TCP は開かない |
| ブリッジの寿命 | Claude Code のプロセスと同じ。**Nemo の再起動・未起動では終了しない**（再接続して initialize をやり直す）。`tools/list` と `initialize` は静的に返す。stdin EOF / SIGINT / SIGTERM / SIGHUP で終了 |
| 繋ぐ先 | 登録は 1 本（`nemo`）。**パッケージ版が起動していればそちら、無ければ dev 版**の socket に繋ぐ |
| 外に出すもの | **固定の高水準ツールだけ**。生の CDP は中継しない。main 内で撃つ CDP メソッドも許可リスト |
| 窓の単位 | **Claude Code のセッション（= ブリッジの接続）ごとに 1 窓**。接続が切れたら閉じる。同じセッション内のサブエージェントはタブで分ける（ページ操作のツールは `tabId` 必須、暗黙の「今のタブ」を持たない） |
| 窓の種類 | 新しい `kind: 'agent'` の `NemoWindow`（フラグ方式にしない。`kind === 'normal'` で絞っている既存の経路から自動で外れる） |
| 窓の出し方 | **全画面にしない普通の窓**（`fullscreenable: false`、`type: 'panel'` にしない）で、デスクトップの Space に出す。`show: false` → `showInactive()` → `blur()` で最背面。**フォーカスは奪わない**。作った時点は `focusable: false`。**key になれないのは Nemo の通常窓が key の間だけ**（小窓・会議の小窓は塞がない。Nemo を前面にせず key になるので、塞ぐと戻す契機が無い）。他アプリや小窓へ移ったら（`did-resign-active` / 通常窓の blur）key になれる状態に戻す。窓を出す瞬間は、別の窓が key なら一時的に塞いで出したあと今の key に合わせて戻す。通常窓が key の間は、実クリックで focusable にする（`setAgentWindowsKeyable` / `syncAgentWindowsKeyable`。2026-10-04 に変更、ログ > 方針変更）。**全画面の Nemo 窓が前面で、同じディスプレイなら表示を保留し、Nemo が前面でなくなってから 1.5 秒待って出す**（Phase 1 で決定） |
| 置き場所 | 画面 2 枚のときは**内蔵ディスプレイ**、1 枚のときも内蔵。`setContentProtection` は付けない（普段の窓と同じくスクショ・画面共有に映る。2 枚のときは内蔵側なので Studio Display の共有には入らない） |
| プロファイル | 専用の永続 partition **`persist:nemo-agent`**。**初版は拡張を載せない**（Bitwarden は後から自作パスワードマネージャーで置き換える前提） |
| 引き継ぎ | Claude が `request_user_action` を呼ぶとそのタブは「ユーザーの番」になり入力系ツールを断る。解除は窓の「Claude に戻す」ボタンか、ユーザーが「続けて」と言った後に Claude が `resume` を呼ぶ。**blur による自動再開はしない**（ターミナルへ戻ったのか 2FA を見に行ったのか区別できない） |
| ダイアログ | `disableDialogs` は使わない（手動時の confirm が黙って false になる）。Electron 内部の `-run-dialog` を差し替え、ユーザーには Nemo の UI で、Claude には `handle_dialog` で答えさせる |
| ツールの語彙 | CiC に寄せる（`tabs_context` / `tabs_create` / `tabs_close` / `navigate` / `computer` / `read_page` / `get_page_text` / `form_input` / `javascript_tool` / `read_console_messages` / `read_network_requests` / `file_upload` / `resize_window` / `browser_batch` 等）。モデルの慣れを流用する。サーバ名は `nemo`（`mcp__nemo__*`）。CiC 固有の `list/select/switch_browser`・`shortcuts_*` は作らない |
| 有効化 | Nemo の設定に「Claude Code からの操作を許可」を置き、**既定 OFF**。一度 ON にすれば以後セッションごとの手作業は無い |

### 調査で分かっていること（実測。2026-09-28、Electron 41.10.6 / Claude Code 2.1.283）

実測に使った使い捨てスクリプトはセッションの scratchpad にあり消える前提。**必要なものは実装時に `scripts/` の検証スイートとして書き直す**。

**Claude Code 側**
- HTTP transport は、起動時に繋がらないと 1・2・4 秒後の 3 回で諦め、`/mcp` で手動再接続が要る。セッション終了の DELETE も来ない → 採らない
- stdio は、対話モードではサーバが死んでも自動再起動されずツールが消える。`nc -U` をブリッジにすると Nemo の再起動・後起動でツールが消えた。**再接続する自作ブリッジ（約 90 行の試作）なら 3 通りとも自動復帰**した
- セッション終了: 正常終了は SIGINT → 100ms → SIGTERM。Claude Code が SIGKILL されてもブリッジに stdin EOF が即届く → Nemo は socket 切断で終了を確実に知れる
- `/clear` `/resume` ではブリッジは再起動されない（`CLAUDE_CODE_SESSION_ID` は古い値のまま）。単位は「プロセス」
- ブリッジに渡る env: `CLAUDE_CODE_SESSION_ID` / `CLAUDE_PROJECT_DIR` / `CLAUDECODE=1`。cwd はプロジェクトルート。窓タイトルに `CLAUDE_PROJECT_DIR` の basename を使える
- 同じプロセス内のサブエージェントは 1 本の接続を**同時に**使い、`_meta` に agentId は来ない（区別できない）
- 画像: 2000px 以内に縮小、500KB 超は JPEG 再圧縮される。**1 メッセージ 16MiB 超で接続ごと切れる** → スクショは Nemo 側で縮小・JPEG 化
- `MAX_MCP_OUTPUT_TOKENS` 既定 25000、`MCP_TIMEOUT` 30s、ツールの idle タイムアウトは stdio 30 分（progress 通知でリセット）
- initialize の `instructions` は 2048 文字で切られて会話に入る。MCP ツールは既定で deferred（`alwaysLoad: true` で即時ロード。2.1.283 の CLI には `--always-load` が無いので `claude mcp add-json` で指定）
- 未知のメソッド（`server/discover` 等）には -32601 を返すこと

**フォーカス・表示**
- `showInactive()` は前面アプリも key window も動かさないが他アプリの窓の上に重なる。`blur()` で最背面へ下がり描画は続く。`show()` / `focus()` / `webContents.focus()` は前面を奪うことがある
- 非全画面の key 窓があるとき、6 通りの出し方すべてで key は動かず、実キーはユーザー側の窓だけに届いた
- **全画面の Nemo 窓が key のとき、エージェント窓を `showInactive` すると key がエージェント窓へ移った**（見えない窓に打鍵が入る）。`prev.focus()` で戻しても次の `blur()` で再び移った。`focusable: false` で防げる見込みだが**全画面では未実測**（Phase 1 で測る）
- 一度も描画していない窓・タブでは CDP のクリック/キーが ack 成功のまま捨てられる。`Emulation.setFocusEmulationEnabled(true)` で全状態で通る。常時入れると隠れていても 60fps 描画（CPU 12〜30 倍）なので**ツール呼び出し中だけ**入れる
- **`hide()` / `minimize()` した窓でページ遷移するとスクショが返らずクリックも落ちる**。最小化は `showInactive()` + `blur()` で前面を奪わず戻せる。⌘H 中は戻すと常用の窓まで出るのでエラーを返す
- `setContentProtection(true)` で screencapture / desktopCapturer / getDisplayMedia に映らなくなった。ページの CDP スクショと `capturePage` は撮れる
- メモリ: エージェント窓 + タブ 1 枚で約 +100MB（小さいページ）

**ネイティブ UI**
- WebContentsView の alert/confirm は親なしの NSAlert（`runModal`）になり前面を奪う。CDP の `handleJavaScriptDialog` で答えても NSAlert は残る
- `-run-dialog` を `web-contents-created` で差し替えると、callback を非同期に保留でき、NSAlert は出ず前面も動かない。window.open の子窓と OOPIF の confirm も同じ経路を通る。保留中はそのタブへの `Runtime.evaluate` と CDP スクショが返らない（`capturePage` は返る）
- `beforeunload`（`will-prevent-unload`）は同期で、非同期 UI では答えられない
- ページの `requestFullscreen`（今の `AUTO_ALLOWED`）で Space 切替と前面奪取が起きた → `fullscreenable: false` で止まる
- `execCommand('copy')` は permission handler を通らずユーザーのクリップボードを上書きした。main world で潰すと止まる
- date / time / color の `showPicker` と `window.print()` は閉じられない UI を残した（窓を destroy しても残る）。`<select>` のクリックは NSMenu が出たまま残る（JS で値を入れる）。`<input type=file>` は `Page.setInterceptFileChooserDialog(true)` で抑止でき、File System Access のピッカーも同じく抑止された
- print / showPicker の差し替えは `Page.addScriptToEvaluateOnNewDocument(runImmediately)` で即効き、遷移後も残る。フラグで分岐させれば実行時に切り替えられる

**CDP と安全**
- **ページ単位の `webContents.debugger` でも `Target.getTargets` / `attachToTarget` で他のタブ・別 partition のページ（UI View 相当）・拡張の SW に入って JS を実行でき、`Network.getAllCookies` で HttpOnly cookie が取れた** → 生の CDP は絶対に外に出さない
- CDP の `Page.navigate('chrome-extension://…')` で拡張ページへ移ると `chrome.storage.session` を読めた。`javascript:` URL への navigate は現在の document で実行された（戻り値は ERR_ABORTED で失敗に見える）→ **スキームは http / https / about:blank に絞る**
- ページには `Electron Isolated Context` の world も並ぶ。evaluate の world は default（`auxData.isDefault`）と Nemo が作る名前付き isolated world に限る
- 同じ webContents への 2 回目の `debugger.attach()` は例外。自動入力の `frame-runner.ts` は相乗りして後片付けで `Target.setAutoAttach(false)` を送る → agent の wc には agent モジュールしか attach しない（Phase 2）
- CDP の `Input.dispatchKeyEvent` / `insertText` は `before-input-event` を発火させない（実キーと `sendInputEvent` は発火させる）→ Nemo のショートカットに化けない。実キーの検出にも使える。CDP のマウスは `before-mouse-event` を発火させる（送出中フラグで区別する）
- 大きいページの `Accessibility.getFullAXTree` は main を約 100ms 止め、ユーザーの窓の打鍵も遅れた → **木はページ内（isolated world）で組み立てて文字列で返す**（約 11ms）。Network イベントの洪水も main を止めるので、必要なツールの呼び出し中だけ enable し件数に上限
- 引き継ぎ後のパスワードは、`javascript:` URL、「パスワードを表示」ボタン → read_page / スクショ（OCR）、コピペのキー（`commands: ['copy'/'paste']`）で読めた。値を消しても React が書き戻す。**伏せ字の対象を広げ（autocomplete が current-password / new-password / one-time-code、一度でも type=password だった要素、taint 後に見た値と一致する値）、スクショの該当矩形を塗る**と read_page・スクショは止まった（AX ツリーを生で使うと漏れる）
- taint を実キー（`before-input-event`）だけで立てると、キーを経ない自動入力（Bitwarden の Fill など）を取りこぼす → isolated world でパスワード欄への input / change を（untrusted を含めて）ツール非実行中に検出する
- CDP の key に `commands: ['paste']` を付けると `clipboard-read` を拒否していてもクリップボードが貼られた → エージェントのキーに copy / cut / paste の commands を付けない
- パッケージ版は **argv の `--remote-debugging-port` / `--remote-debugging-pipe` を受け付けて CDP を開く**（dist 1.2.19 で実測。pipe では拡張の SW まで列挙できた）。`index.ts` は env しか見ていない。main 冒頭で `app.commandLine.removeSwitch()` すれば塞がる（素の Electron で修正前 FAIL → 修正後 PASS）
- unix socket の sun_path は 104 バイトまで。`<userData>/agent.sock` は 57 バイトで収まる。検証用の使い捨て userData は長くなるので短いパスへの差し替え口（`!app.isPackaged` 限定）が要る

**Nemo の構造**
- 窓は `NemoWindow`（`registry.ts`）、種類は `WindowKind = 'normal' | 'mini'`。セッション保存 `collectSession`・フォーカス履歴 `rememberNormalWindowFocus`・⌘O の移し先 `mostRecentNormalWindow` は `kind === 'normal'` で絞っている
- `canHostAdditionalTabs`（`kind === 'normal'`）を agent に流用すると「1 タブの器」になる → 述語を分ける: 外から来るタブの受け皿になるか・タブを複数持てるか・共有状態（履歴・定義・アーカイブ）に参加するか（Phase 2）
- `remember()` / `rememberClosedTab` / `sweepSleep` / `sweepArchive` は isPrivate しか見ていない → agent を外す
- ⌘T 等のメニューは `focusedOrFirstWindow`、拡張の tabs.create は ECE の lastFocusedWindowId、外部アプリの URL は常に小窓（`persist:nemo`）
- `setOverlay()` / `focusForegroundPage` / `presentMiniWindow` が `focus()` を呼ぶ → agent 窓では呼ばない
- ダウンロードは `showSaveDialogSync`（main を止める）→ agent 窓では固定フォルダにダイアログなしで保存
- 通常窓の alert/confirm も親なし NSAlert で前面を奪っている（今回は agent 窓だけ差し替える。通常窓への展開は別判断）
- 会議の検知（`call-coordinator.ts`）は全ウィンドウのタブを候補にする → agent を外す
- 検証スイートは登録（`scripts/lib/verify-targets.mjs`）と配線（`scripts/verify-all.mjs`）の両方が要る（リポジトリ CLAUDE.md）

**CiC について**
- CiC のツールは少数の CDP（`Input.*` / `Page.captureScreenshot` / `Runtime.evaluate` / Runtime・Network のイベント / `Page.handleJavaScriptDialog`）と executeScript の DOM 走査でできている。`read_page` は Accessibility ドメインを使わず content script で ref 付きの木を作る。`find` は内部で小さいモデルを呼ぶ
- 空のタブグループが溜まる直接の原因は Chrome の「新しいタブグループを自動保存してブックマークバーに固定」（`auto_pin_new_tab_groups: true`）。Nemo では窓ごと閉じるので構造的に起きない
- Claude Code 2.1.283 の CiC はローカルの native host ではなくクラウド中継（`wss://bridge.claudeusercontent.com`）で拡張と話す
- CiC の安全策のうち取り入れるもの: スコープ（自分の窓のタブだけ）、操作中のドメイン変化での中止、`chrome:` / `chrome-extension:` 等への不接触、ページ由来テキストの不可視文字（Default_Ignorable と U+2800）除去、file_upload はバイト列（10MB）、操作中インジケータと停止、`beforeunload` を既定で破棄しない

### 残るリスク（受け入れる）
- 同じユーザーで動く任意のプロセス（npm の postinstall 等を含む）が `agent.sock` に繋いで agent partition を操作できる。0600 で防げるのは他ユーザーだけで、接続時の pid / プロジェクトは自己申告。`claude` 自体を起動すれば正規の経路で繋げるので原理的に排除できない。今の cookie 暗号化（Keychain）で守っている範囲より緩く、露出時間は CiC（拡張が待機中のときだけ）より長いことを受け入れ、既定 OFF・窓での可視化・専用 partition で被害範囲を絞る（1回目のレビューで決定）
- ログインが済んだ後は、プロンプトインジェクションで Claude がそのセッションを使って API トークン等を作れる。既知の危ないページ（トークン発行・OAuth 同意・sudo）では Claude に navigate も入力もさせず、`request_user_action` でユーザーに頼ませる（Phase 7）。これは URL で「取りこぼさない側」の網で、迂回は防がない:
  - `javascript_tool` から同じ origin へ `fetch` すれば、危ないページを開かずにトークンを作れる
  - 別プロセスの iframe（OOPIF）には taint・スクショの塗り・print / copy の塞ぎが届かない（埋め込みのログイン欄・カード欄）
- 専用 partition にもログインは溜まる（Google にログインすれば Gmail・Drive にも届く。ブロックリストの既定は空にしたので、メール経由のパスワードリセットも含めて届きうる）。ログイン中のサイト一覧と消去を用意する（Phase 7）
- 引き継ぎの前に Claude が `javascript_tool` でページに仕込んだコード（入力を拾って DOM・title へ書く / 外へ送る）は塞げない。taint は「引き継ぎ後の JS を断る」だけ。プロンプトインジェクションでパスワードが持ち出されうることを受け入れ、ログインを頼むときは新しく開いたページで入れてもらう運用で補う（実装レビュー 1 回目で決定。再読み込みで消す案は、読み込み直しでフォームの途中状態が消えるため採らない）
- マジックリンク型のログインは、メールのリンクが常用側の小窓で開くためエージェント窓がログインされない（今の Chrome と同じ）。「Claude の窓で開く」で補う（Phase 7）

### 方針変更
- **`setContentProtection(true)` を外した**（v1.2.20 のリリース後）。付けていると OS がその窓をスクショ・画面収録から外すので、自作のスクショツール（capit）でも撮れず、不具合の報告や Claude に画面を渡すのに困った。普段の Nemo の窓にも同じログイン済みの管理画面が出ていて保護していないので、Claude の窓だけ守っても範囲はほぼ増えない。画面 2 枚のときは内蔵側に出るので Meet（Studio Display の共有）には元々入らない
- MCP サーバは SDK を使わず JSON-RPC を手で書いた（ブリッジ ⇔ Nemo は独自の 1 行 JSON、Claude Code ⇔ ブリッジだけが MCP）。依存を増やさないため
- 検証スイートは 3 本に分けず `verify-agent` 1 本にした（アプリの起動を 1 回ぶんにまとめるため）。`OPT_IN_ONLY`（アプリを 2 回起動する）
- JS ダイアログをユーザーに出すのは Nemo の overlay（prompts.ts）ではなく、**窓に付いたシート**（親付きの非同期 `showMessageBox`）にした。main を止めず、アプリモーダルにもならない。Claude の番は保留して `handle_dialog` で答える
- 「既知の危ないページはユーザー確認」は、**Claude に navigate も入力もさせず `request_user_action` で頼ませる**形にした（確認ダイアログを足すより単純で、確認を Claude に誘導されて押す余地が無い）。そのページから離れる navigate と tabs_close は通す（通さないと Claude が動けなくなった。自走検証で踏んだ）
- ログインが残っているサイトのまとめ方は `tldts` を入れず、`co.jp` 等の 2 階層目を見る近似にした（依存と lockfile の再生成を避ける。表示と消去の単位に使うだけ）
- file_upload の範囲は roots/list ではなく「絶対パス・O_NOFOLLOW・通常ファイル・合計 10MB」をブリッジで見る形にした。ブリッジは Claude Code の子で同じ権限なので、読める範囲は Claude Code と同じ（Nemo にパスを読ませないのが要点）
- ブロックリストは UI を作らず `settings.json` の `agentBlockedHosts` で編集する（既定は空）
- ブリッジの tools/list はビルドで生成せず、`agent-tools.js` をブリッジの隣に同梱して実行時に import する（正本は 1 か所のまま。生成の手順を増やさないため）
- agent の webContents への debugger の assert は置かず、自動入力の入口（`runAutofill`）で agent を拒否して `frame-runner` が agent に付かないようにした

- **エージェント窓を「blur のたびに focusable:false」から「Nemo の通常窓が key の間だけ focusable:false」に変えた**（2026-10-04）。
  前者だと、ターミナル等が前面のときにデスクトップのエージェント窓をクリックすると、Nemo の前面化で key になれない窓が飛ばされて
  常用の全画面窓が key になり、macOS がその Space へ切り替えた（「Claude のウィンドウを見ようとすると常用の窓へ移動させられる」）。
  実クリックで focusable にしても 0.4 秒後に常用窓へ戻り、上端のドラッグ領域では mouseDown 自体が届かない。
  使い捨ての Electron（4 通り）と、ビルドした本体（使い捨てのプロファイル・通常窓を全画面・別アプリを前面にして合成クリック）の両方で、
  修正前は全画面の Space へ切り替わり、修正後はデスクトップのまま Claude の窓が key になることを確かめた。通常窓へ戻ると
  `agent.window_keyable false nemo_window_focus` で塞がる（Phase 1 の打鍵の横取り対策は残る）。

### 見送り（理由）
- 実キー・実クリックで**実行中の**入力ツールを中断する: ツール開始時に「窓が key なら断る」で大半を防げる。途中での中断は入力の途中状態が残るので、実運用で困ってから考える
- `tabs_context` の `openedBy: 'user'`・`javascript_tool` を設定で OFF にする口・console / network のドメイン変化でのリセット・`browser_batch`・`find`・`gif_creator`: 初版では要らない（Claude は逐次に呼べる）
- 自走検証に入れていないもの: OOPIF 内のクリック・未描画タブでの入力・window.open の子や iframe のダイアログ・React の目のボタン（いずれも調査のスパイクで実測済み）。前面アプリと key が動かないことは Phase 1 と人の確認で見る
- `setup-claude-mcp.sh` への登録とグローバル CLAUDE.md の書き換え: パッケージ版にブリッジが入って（リリースして）から。今登録すると、存在しないパスのブリッジが全セッションで失敗する
- クリック前の `DOM.getNodeForLocation` による拡張 iframe の判定・キー前の `focusedFrame` 確認: agent partition には拡張を読み込まず、`chrome-extension:` のサブフレームはナビゲーション方針で弾いているので、今は当たる相手がいない。パスワードマネージャーを agent 窓に載せるときに入れる（実装レビュー 1 回目）
- 自走検証に入れていないもの（2）: CDP 許可リスト外（`Target.*` / `Storage.*` 等）が断られること・2 接続で窓 2 枚・SIGKILL での後始末・最小化からの復帰で前面を奪わないこと・パスワードを入れる口に CDP から届かないこと・スクショの伏せ字・クリップボード不変。実装で確かめた範囲に留め、壊れた実例が出たら足す（実装レビュー 1 回目）
- 実キーの `before-input-event` でパスワード欄の taint を立てる受け皿: ページ側の `onUserValue` がユーザーの番に必ず記録する形にしたので、二重にしない
- ブロックリストの back / forward・popup の最初の読み込みでの判定、`javascript_tool` からの `fetch` を危ないページの URL で止める `webRequest`、OOPIF への注入（print / showPicker / copy の塞ぎ・taint・塗り）: いずれも足す仕組みが大きい。ブロックリストの既定は空、危ないページは「取りこぼさない側の網」の位置づけなので、初版は main frame の遷移と入力で止める範囲にする（実装レビュー 1 回目）
- ログイン中のサイト一覧に localStorage だけのサイトを出す・`read_network_requests` の URL のクエリを伏せる: 実際に困ってから（実装レビュー 1 回目）
- `registry.ts` を OWNERS に載せて agent を回す: 未登録ファイルを載せるとフル実行から 1 スイートに絞られる改悪になる（リポジトリ CLAUDE.md の決まり）
