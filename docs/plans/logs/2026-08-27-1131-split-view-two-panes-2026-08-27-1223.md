**対応**: P0 は0件（収束）。

P1 は3件すべて反映。(1) 未読の扱いが `activeTabKey` 起点なので相方に未読ドットが残る件を、`applyVisibility()` で「見えているタブ全部の未読を落とす」に加え、**付ける側**（読み込み完了時の判定と Live Folder の `activeUrls`）も `visibleTabKeys` 基準へ直す step を追加（実コードで `registry.ts:618` の未読判定と `activeUrls` が `getActiveTab()` だけを見ていることを確認）(2) `splitTabs` の拒否条件に「一方の URL がいま Live Folder の一覧に載っている」を追加し、`liveFolderOpen` と同じく main で照合する方針にした。IPC を直接叩く検証も Phase 7 に追加 (3) `moveTabToWindow` でも解除前に相方を控えて移動後に選ぶ step を追加（`removeTab` と同じ罠）。あわせて Phase 7 のウィンドウ移動検証を「ペアの後ろに対照タブを置いてから右を移す」に強化。

P2 1件も反映。`normalizeSession` の重複添字は「競合したペアを全部落とす」と規則を確定（先着を残すと結果が実装順に依存し、冪等性検証の期待値が決まらないため）。1行で済み、次のレビューの突っ込みどころも増やさないと判断した。

Q は2件（器のクリップ不発時の継ぎ目の扱い／分割後に片側が Live Folder の対象になった場合の扱い）。どちらも人間の決定待ちのため plan には反映しない。
