   実測は打ち切り判断ではなく「次に何を削るか（ビルドのキャッシュ / アプリ起動の使い回し）」の材料。

   随伴は維持したうえで、`restart` ブロックが `want()` と無関係に無条件で走らせている
   spike / phase1 / pins の write+read も絞れるようにする。永続性の検証を落とさずに
   `--changed` の下限コストを下げる。再起動そのものは1回に保つ。
   随伴を外す案（永続性をコミット前のフルに任せる）は、復元まわりの退行がコミット直前まで
   見つからないため不採用。

これに伴い Phase 1 に「`restart` ブロック内の無条件実行を `want()` で絞る」ステップを追加し、
検証項目にも「`restart` の中で split の write/read だけが走り spike / phase1 / pins は走らない」を追加した。
