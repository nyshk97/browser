## P1
- `src/shared/permissions-query-shim.js:installPermissionsQueryShim`（`facades`） — `query()` のたびに `facades` へ entry を足し、実 status にも `change` リスナーを 1 本ずつ足すが、取り除く経路が無い。Meet は query を繰り返し呼ぶので、通話中ずっと Proxy とリスナーが溜まり、`devicechange` / getUserMedia 成功のたびに `reevaluateAll` が entry 数ぶん `enumerateDevices()` を撃つ（O(n) が単調増加）。/ 長時間ページで確実に増える一方のリークで、まさに本命の Meet が該当する。/ `facades` を `Map<name, entry>` にして name ごとに 1 entry を再利用する（同じ name の 2 回目以降は既存 facade を返す）。ついでに毎 query の `enumerateDevices()` も 1 本に畳める。
- `src/shared/permissions-query-shim.js:installPermissionsQueryShim`（`reevaluate` の自前 change 発火） — 合成イベントが `new Event('change')` のままなので `event.target` が **null**。`status.onchange = (e) => use(e.target.state)` 型のハンドラは prompt→granted の遷移で TypeError になり、その例外は `catch {}` に飲まれて黙って落ちる。/ 「許可したのに UI が未許可のまま」という、今回直したかった詰みの別バージョンをピンポイントで作る。/ 発火前に `Object.defineProperty(event, 'target', { value: facade })`（`currentTarget` も同様）を足すか、`local` 側を実 `EventTarget` にして dispatch する。
- `src/shared/permissions-query-shim.js:makeFacade`（`addEventListener` の二重登録） — facade 経由のリスナーを `local.listeners` と実 status の**両方**に登録している（`scripts/permissions-query-shim.test.mjs` の「実 status 側にも届く」がこれを固定している）ため、実 status が本当に change したときにページのリスナーが 2 回呼ばれ、しかも実イベント側の `e.target.state` は**読み替え前の値**（granted）になる。`onchange` は facade 内で完結していて転送しないので、経路ごとに挙動も食い違う。/ 読み替えの一貫性が経路依存で崩れ、シムが `prompt` と言っている裏で `granted` がページに見える。/ 実 status へは `makeFacade` 内の再評価用リスナー 1 本だけを張り、ページのリスナーは `local` 側だけで扱う（`removeEventListener` も同様）。テストの期待値も「実 status には転送しない」に合わせて直す。

## P2
- `src/shared/permissions-query-shim.js:installPermissionsQueryShim`（`permissions.query` / `getUserMedia` の差し替え） — 全 http/https ページで `navigator.permissions.query.toString()` と `mediaDevices.getUserMedia.toString()` が `[native code]` でなくなる。anti-bot（reCAPTCHA / Cloudflare 等）はここを見ることがあり、Meet と無関係なサイトの判定に影響しうる。/ 差し替えた関数に `name` / `length` を合わせ、`toString` を元関数のものへ委譲しておくと露出面が減る。
- `src/main/page-shim.ts:registerPageShim` — `extension-shim.cjs` のパス組み立てが `src/main/extensions.ts` の `preloadDir` と重複している。ビルド出力レイアウトが変わると片方だけ直され、症状は `page.shim_missing` ログ（＝シークレットだけ Meet 詰み再発）という気づきにくい形で出る。/ `preloadDir` を `paths.ts` 等に出して両者から参照する（`extensions.ts` を import すると循環になるので置き場所は第三のモジュール）。
- `scripts/verify-phase1.mjs`（シークレットウィンドウ検査ブロック） — private target の消滅を最大 10 秒待つが、消えなかった場合に check も skip も出さず素通りする。/ コメント自身が「閉じ忘れると後続が不安定」と書いている状況が、後続検査の謎の失敗としてしか現れない。/ ループ後に `left` を見て、残っていたら FAIL か skip を 1 件出す。
