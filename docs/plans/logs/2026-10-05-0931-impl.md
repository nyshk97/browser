## P1
- `src/main/devtools-shim.ts:hookExtensionApis` — 横取りが DevTools 画面の `Runtime.evaluate` にしか入っていない。そのため 2 つの穴がある。(1) 初回の起動で、`devtools-opened` から拡張の登録まで 100ms しか余裕がない（170ms と 270ms、1 台で 1 回測っただけ）。(2) DevTools の画面を読み直すと、`__nemoExtensionApis` と `__nemoHooked` は消える。「`devtools-opened` がまた来る」はコメントに書いてあるだけで、smoke でも差分の中でも確かめていない / 遅いマシンで登録が先に来たり、読み直しで横取りが外れたりすると、その DevTools では GraphQL パネルが黙って出なくなる。痕跡は `late` のログ 1 行だけ（読み直しの場合はそれすら残らない）/ root セッションにも `Page.enable` と `Page.addScriptToEvaluateOnNewDocument(HOOK_EXTENSION_APIS_SOURCE)` を入れる。こうすれば読み直したあとの document では、登録より前に横取りが入る（今の evaluate は初回用に残す）。あわせて「読み直しても出る」を実測するか smoke の手順に足し、コメントは実測した内容に合わせる
- `src/shared/devtools-extension-api.js:buildDevToolsFrameSource` — 組み立てたスクリプトが sloppy mode なので、`globalThis.chrome = Object.create(...)` が失敗しても例外にならない / 将来 Chromium が `window.chrome` を書き込めない（writable: false）にすると、差し替えの失敗が「chrome の複製に失敗した」として出ない。表に出るのは後ろの補完と `chrome.devtools` の TypeError だけで、原因から遠いログしか残らない。#2 の調査で一番効いた観測点がここにあたる / 代入のあとに `globalThis.chrome === original` なら throw する（または IIFE の先頭に `'use strict'` を置く）。そうすれば `guarded` の「chrome の複製」に失敗が出る

## P2
- `src/main/devtools-shim.ts:attachDevToolsExtensionShim` — `chrome.devtools` のスクリプトは、子 target が付いた時点の写しをそのセッションの `addScriptToEvaluateOnNewDocument` に固定している / DevTools の画面が同じ origin へ `setInjectedScriptForOrigin` を呼び直すと（テーマの変更など、呼び直す経路があるなら）、同じ frame を読み直したときに古いスクリプトが走る / 実害が見えたら、`Page.removeScriptToEvaluateOnNewDocument` で入れ直す仕組みを考える。今は「付いた時点の写し」という前提をコメントに 1 行書いておく程度でよい
