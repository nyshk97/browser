# Nemo: 自作ブラウザ（Arc 代替）

## 概要・やりたいこと

Arc から自作ブラウザ「Nemo」へ乗り換える。

Arc の速度や基本的な使い勝手には満足しているが、以下の理由で自作したい:

- **かゆいところに手が届くようにしたい**: 使っていく中で「こういう機能が欲しい」と思ったときに、すぐ自分で実装できる状態にしたい
- **不要な機能を視界から消したい**: Arc の AI 機能などほとんど使っていない機能が UI を占めている
- **PC 移行・複数端末での共有が面倒**: Arc はピン留めアイテムなどが移行できず、端末間の共有も難しい
- **将来的なパーソナライズの土台**: 自分の経歴・好み・個人情報を環境変数やファイル・DB といった永続層に持たせられれば、本当に自分向けの AI 補助機能を載せられる。ただし具体的なアイディアは現時点では無く、**まず「明らかに必要なもの」だけを作り、使いながら育てる**

現時点のゴールは **「Arc 相当の使い勝手を Nemo で再現し、既定ブラウザを Nemo に切り替える」** こと。自作機能はその後に足していく。

## 前提・わかっていること

### 事実確認したこと

#### Arc について

- **Arc は Electron ではない**。Swift のネイティブ UI + Chromium を直接組み込んだアプリ（Vivaldi / Brave と同系統）。だから Chrome 拡張も DevTools も完全互換で動く
- **Arc のデータは素の JSON で読める**（移行スクリプトは機械的に書ける）:
  - `~/Library/Application Support/Arc/StorableSidebar.json`（2.5MB）
    - `sidebar.containers[1].spaces` … スペース定義（2件）
    - `sidebar.containers[1].items` … タブ・フォルダ（111件）。`data.tab.savedURL` / `savedTitle`、`childrenIds` でフォルダ階層、`parentID` で所属
    - `sidebar.containers[1].topAppsContainerIDs` … Favorites（サイドバー上部のアイコングリッド）
  - `~/Library/Application Support/Arc/StorableArchiveItems.json`（1.1MB, 1326件）… アーカイブ済みタブ

#### `electron-chrome-extensions@4.9.0`（npm から取得して LICENSE / README を直接確認）

- **ライセンスは GPL-3.0 と Patron License のデュアル**。npm 上は `SEE LICENSE IN LICENSE.md`、README は "GPL-3. For proprietary use, sponsor me" と明記。**MIT ではない**
- **README の Limitations に明記された制約**:
  - `Chrome extensions are not supported in non-persistent/incognito sessions.` → **incognito セッションに拡張はロードできない**
  - `Usage of Electron's webRequest API will prevent chrome.webRequest listeners from being called.` → **Electron 側で `webRequest` を使うと拡張側の `webRequest` が死ぬ**。広告ブロックを内蔵する場合は宣言的ブロック（DNR）で実装するか、拡張に寄せるかの二択
  - `Service worker preload scripts require Electron's sandbox to be enabled.` → **`sandbox: true` は セキュリティ要件であると同時に拡張の動作要件**
  - `The latest version of Electron is recommended. Minimum support requires Electron v35.0.0-beta.8.` → **動作する組み合わせは自分で固定するしかない**
  - すべての background script が persistent 扱いになる
- 現在の Electron 最新は **43.4.1**。Electron 42 以降で `electron-chrome-extensions` のアイコン・popup が壊れるという未解決報告がある（`samuelmaddock/electron-browser-shell#184`）ため、**「最新版」ではなく本番採用予定の組み合わせで検証する**

#### Electron ネイティブの拡張 API サポート（公式ドキュメントを確認）

- Electron 自身が対応を明記しているのは **`chrome.devtools.*` / `chrome.extension`(部分) / `chrome.management`(部分) / `chrome.runtime`(部分) / `chrome.scripting` / `chrome.storage`(**`local` のみ**) / `chrome.tabs`(`sendMessage`・`reload`・`executeScript`・`query`・`update` のみ) / `chrome.webRequest`** だけ
- **`chrome.declarativeNetRequest` は一覧に無い**
- → 実用的な拡張互換は**ほぼすべて `electron-chrome-extensions` が補っている**。この依存の重さが Phase 0 をゲートにする理由そのもの

#### `electron-chrome-web-store@0.13.0`（MIT。README の API 定義を直接確認）

- CRX3 を自前で剥がす実装は不要
- **`installExtension(extensionId, options)` にバージョン指定パラメータが存在しない**（options は `session` / `extensionsPath` / `loadExtensionOptions` のみ）。**Web Store の最新版しか入らない**
- **`installChromeWebStore({ autoUpdate })` の既定値は `true`**（起動時と5時間ごとに自動更新される）
- 一方で回避手段がある:
  - `allowUnpackedExtensions` … unpacked 拡張のロードを許可する
  - `loadAllExtensions(session, extensionsPath, { allowUnpacked })` … **指定ディレクトリから直接ロードできる**（Web Store を経由しない）
  - `allowlist` / `denylist` … インストール可能な拡張 ID を制限できる
- → **バージョン固定は「Web Store から入れる」のでは成立せず、不変 artifact を自分で保持して直接ロードする**設計が必須

#### 開発環境

- 開発機は個人 PC（Apple Silicon / macOS 15）。Node v24.13.0 / pnpm 10.33.0 / gh 導入済み。**`age` は未インストール**（Brewfile 経由で追加が必要）
- 署名・notarize の基盤は既存の自作アプリのものをそのまま使える（Developer ID Team と notarytool プロファイルは手元の設定を参照する。**public repo には書かない**）

### 決定事項

| 論点 | 決定 |
|---|---|
| アプリ名 | **Nemo**（常用版 `local.nyshk97.nemo` / dev 版 `local.nyshk97.nemo.dev`） |
| 土台 | Electron + `BaseWindow` + タブごとの `WebContentsView` + `electron-chrome-extensions` |
| ライセンス / repo | **本体 repo を public にして GPL-3.0 で配布**。`electron-chrome-extensions` の copyleft に準拠する |
| UI | TypeScript + React。**実装前に DESIGN.md と HTML モックで見た目を確定する** |
| 拡張 | 主要なもの（Bitwarden 等）が動けば OK。動かない小さい拡張はブラウザ本体の機能として作り直す |
| 拡張の取得・更新 | **`autoUpdate: false`**。lock した**不変 artifact を保持して直接ロード**する。更新は明示的な操作でのみ行い、失敗したら旧 artifact に戻す |
| サイドバー | **スペース概念なし**。Favorites / ピン留め（フォルダ可）/ 一時タブ の3層フラット |
| 自動アーカイブ | 既定 **24時間**。設定で変更・OFF 可 |
| セッション | 単一セッション + **拡張なしのシークレットウィンドウ**（Chrome の既定挙動と同じ） |
| ウィンドウ | 複数ウィンドウ対応、左右分割なし |
| 同期 | private git repo に JSON を置き、**手動** pull / push。全端末で完全に同じ状態 |
| 同期の境界 | **常用データ（Application Support）と git 作業コピー（staging）を分離**し、検証を通してから原子的に import / export する |
| データ形式 | 同期対象（設定・ピン留め・Favorites）= 人間が読める JSON / 履歴・アーカイブ = ローカル SQLite |
| シークレット | `age` で暗号化して同期 repo に格納。**ただし利用者が現れる Phase 3 まで着手しない** |
| キーバインド | Arc を踏襲（⌘T コマンドバー / ⌘S サイドバー / ⌘D ピン留め等）。設定ファイルで変更可 |
| Arc からの移行 | `StorableSidebar.json` をパースする冪等なスクリプトとして実装 |
| 配布 | notarize + GitHub Release + アプリ内自動更新（electron-updater） |
| Chromium 追従 | Renovate で自動 PR。**拡張互換の smoke test を必須ゲートにし、落ちたら Electron を据え置く** |
| dev 版 | 表示名・bundle id・アイコンを分離。**データも分離**し、常用版からコピーするコマンドを用意 |
| repo 構成 | `nemo`(**public**, GPL-3.0, ソース + Release) / `nemo-config`(private) の**2つ** |
| 移行の進め方 | 段階移行（Arc と併用期間を置き、Phase 2 完了時に既定ブラウザを切り替え） |

> **repo を3つから2つに減らした理由**: 配信 repo を分ける目的は「ソースを private に保ったまま配布 URL を公開する」ことだったが、本体を public にした時点でその理由が消えた。GPL のソース提供義務の観点でも、バイナリとソースが同じ repo にある方が対応が自明になる。既存の自作アプリと運用を揃えたいなら分けたままでもよい。

### 認識しているリスク

1. **Arc のログインセッションは移行できない**。乗り換え時に全サイト再ログインになる（Bitwarden があるので現実的だが、2FA のあるサイトは手間）
2. **Electron と `electron-chrome-extensions` の互換性は壊れやすい**。Electron を上げた瞬間に拡張が死ぬ可能性があるので、last-known-good の組み合わせを記録し、いつでも据え置ける運用にする
3. **拡張のバージョン固定は Web Store 経由では成立しない**。不変 artifact を自分で保持しない限り、2台でバージョンが揃わない・lock 版に戻せない
4. **多数タブのメモリ**。`WebContentsView` はタブごとに実プロセスなので、非アクティブタブの sleep / discard 機構が必要。また **`BaseWindow` を閉じても子 `WebContentsView` の `webContents` は自動破棄されない**ので、明示的に破棄しないとリークする
5. **任意のサイトを開くアプリなので、セキュリティ境界の設計を最初に固める必要がある**。Electron は permission handler を設定しないと権限要求が自動許可され得る
6. **本体 repo が public になるため、個人情報をコードに入れられない**。ブックマーク・履歴・シークレットはすべて `nemo-config`（private）側に置く

## ログ

### 試したこと・わかったこと

- `electron-chrome-extensions@4.9.0` を npm から取得して LICENSE / README を直接確認した。ライセンスは GPL-3.0 + Patron License のデュアルで MIT ではない。README の Limitations に incognito 非対応・`webRequest` の相互排他・sandbox 必須が明記されている
- `electron-chrome-web-store@0.13.0`（MIT）の API 定義を確認した。**`installExtension` にバージョン指定がなく、`installChromeWebStore` の `autoUpdate` 既定値は `true`**。一方 `loadAllExtensions` / `allowUnpackedExtensions` / `allowlist` があるので、Web Store を経由せず不変 artifact を直接ロードする方式が取れる

- Electron 公式ドキュメントの対応 Chrome 拡張 API 一覧を確認した。`chrome.storage` は `local` のみ、`chrome.tabs` は5メソッドのみという極端に狭い範囲で、**`chrome.declarativeNetRequest` は含まれていない**。実用的な互換はほぼ全て `electron-chrome-extensions` に依存している

#### Phase 0 スパイクで分かったこと（2026-08-23）

- **Vault をアンロックしてもツールバーのアイコンがすぐ切り替わらない**（ロックアイコンのまま。しばらくして badge「2」付きの通常アイコンになる）。`<browser-action-list>` は `crx://extension-icon/...?t=<iconModified>` でキャッシュ回避しているので、アイコン URL の問題ではなく、**Bitwarden がアイコンを更新するきっかけにしているイベントが届いていない**線が濃い。実害は見た目だけなので Phase 1-8 に送った

- **「更新しても拡張の設定が飛ばない」は機械検証できる**。使い捨てのデータディレクトリで `chrome.storage.local` に印を書き、版を張り替えて起動し直して印が残っているかを見ればいい（`mise run verify:ext-update`）。実 Vault を使わずに設計の肝を毎回確かめられる

- **`ext:update` が「lock の派生フィールドを1つ消し忘れる」バグを踏んだ**。版を張り替えるとき `sha256` は空に戻したが `treeSha256` を戻し忘れ、旧版の hash と新版の実体を突き合わせて必ず失敗した。**更新経路は手で回すまで誰も通らない**ので、偽の拡張（鍵を生成して ID を決め、zip をキャッシュに直置き）で「初回 → 更新 → ロールバック」を回す密閉テストを置いた。ネットワークもリポジトリ本体の lock も使わない。バグを戻すと確かに2件落ちることまで確認した
- 失敗したときの状態は壊れていなかった（ツリー hash の照合が原子的な入れ替えより前にあり、`writeLock` はループの後なので、lock も展開済みディレクトリも無傷のまま止まる）
- **`ext:rollback` は git 依存なので、まだ1つもコミットが無いリポジトリでは使えない**。git から復元できないときは `mise run ext:update <version>` を案内するようにした

- **`chrome.commands` が実質未実装**。`getAll()` は manifest の6件を返すが `shortcut` はすべて空文字で、`electron-chrome-extensions` のソースには `globalShortcut` も `commands.onCommand` の dispatch も1つも無い。`onCommand.addListener` は呼べてしまうので「登録できたのに永久に発火しない」形になる。**パスワードマネージャはキーボードで使うものなので、Nemo 側での実装が事実上必須**（Phase 1-8 に追加）
- **実アカウントの Bitwarden で自動入力が動いた**（Qiita のログインフォームに popup の項目クリックからメールアドレスとパスワードが入る）。Vault のアンロックと再起動後の復元も確認できた
- **初回ログインで 2FA コードを送ると popup がスピナーのまま止まる**。ただし**ログイン自体は成功している**（再起動するとアンロック画面が出る）。popup ↔ service worker のメッセージングが疑わしい（`Unchecked runtime.lastError: Could not establish connection.` が出続けている）

- **`electron-chrome-extensions` には「バックグラウンドタブ」の概念が無い**。`store.addTab()` が `tab-added` を emit → `TabsAPI.observeTab` → `onActivated` → `store.setActiveTab` → `impl.selectTab` と流れ、**追加したタブを無条件でアクティブにする**。`chrome.tabs.create({ active: false })` に対して「こちらが selectTab を呼ばない」だけでは足りず、addTab 直後に元のアクティブタブへ戻す必要がある。自動テストを書いて初めて分かった（`window.open` の検証だけでは素通りする）
- **アーカイブの sha256 だけでは拡張の完全性を保証できない**。展開後の JS を書き換えても通ってしまうため、lock に「展開・key 注入まで済んだツリー全体の hash」を持たせ、**ロード前に照合して一致しなければ `loadExtension` を呼ばない**構成にした。Bitwarden のツリーで実測 60ms なので起動時に毎回回せる
- **`localhost:8787` は URL としては scheme `localhost:` に見える**。コマンドバーの入力検証を素直に書くと弾かれてローカル開発が詰む。`host:port` を先に救う必要がある（ナビゲーション判定のユニットテストを書いて発見した）
- `sandbox: true` の preload を CJS で出す件に加えて、**ブラウザ UI の CSP は dev と本番で分ける**必要がある。Vite の HMR は inline script と ws 接続を使うため、本番の `script-src 'self'` のままでは dev server 経由で描画できない

- 採用した組み合わせは Electron **41.10.6**（Chromium 146）+ `electron-chrome-extensions` **4.9.0** + Bitwarden **2026.8.0**。42 系は既知の破壊報告があるため上げていない。`docs/compat.md` に記録した
- **Bitwarden の公式 GitHub Release にバージョン付き artifact があった**（`bitwarden/clients` の `dist-chrome-<version>.zip`）。URL + sha256 を lock に書くだけで再現でき、バイナリを自前で抱える必要は無い
- **GitHub Release の zip には `manifest.key` が無い**。そのままロードすると unpacked 拡張として扱われ、拡張 ID がロード元パスから導出される。Nemo の展開先はバージョンを含むため、**版を上げるたびに ID が変わって `chrome.storage`（= Vault の設定）が失われる**。Web Store の CRX から公開鍵を一度だけ取り出して lock に持ち、展開時に `manifest.json` へ注入することで ID を固定した。2026.8.0 → 2026.7.0 → 2026.8.0 の往復で ID が不変なことを実測で確認した
- **`chrome.declarativeNetRequest` は名前空間ごと存在しない**ことを実測で確定した（Phase 3 の広告ブロック内蔵は DNR ではできない）。`chrome.sidePanel` も名前空間はあるが `setOptions` が無い。一方 `chrome.storage` は `local` / `session` / `sync` すべて動き、`contextMenus` / `webNavigation` / `notifications` / `privacy` も利用できた
- **service worker を止める API が Electron に無い**（`startWorkerForScope` はあるが stop が無い）。「SW を停止してから popup を開く」試験は idle 停止を待つしかないので、UI に再起動ボタンを置いて代替した
- `sandbox: true` の preload は **ESM をロードできない**ため preload だけ CJS で出す必要がある。また `electron-chrome-extensions/browser-action` は preload にバンドルしないと動かない（sandbox 下では `node_modules` を require できない）
- ブラウザ UI とページを**別セッション**（`persist:nemo-ui` / `persist:nemo`）に置いた。同居させると `<all_urls>` の content script がブラウザ UI 自身に注入されうる。`<browser-action-list>` は `partition` 属性で別セッションの拡張を参照できるので分離しても成立する


### 方針変更

#### Phase 0（2026-08-23）

- **回帰テストの後始末を `t.after()` に移した**。「SIGTERM を握り潰す子」や「`kill` を差し替えた子」を意図的に作るテストで、復元処理が assert の後ろにあった。つまり**回帰を検出したときに限って**子が生き残り、テストランナーが終われなくなる（実際に孤児プロセスが残っていた）。バグを戻した状態で走らせ、3件 fail しても孤児が残らず完走することを確認した

- **後片付けの可否を「停止処理が成功したか」で判断していたのが誤り**だった。追跡配列を `splice` で空にしてから停止していたため、途中の停止に失敗しても最後の後片付けは空配列を見て成功扱いになり、使用中の一時ディレクトリを消した。**起動した子は追跡配列から外さず、可否は毎回 `spawned.filter(isChildAlive)` で計算する**形に変えた。危険な書き方が戻っていないかをソースレベルの回帰テストでも固定した
- **`lstat` の全例外を「存在しない」扱いにしていた**（EACCES でも起動中判定を素通りした）。`ENOENT` のときだけ fail-open にした
- **`Promise.race([p, sleep(ms)])` はタイマーを残す**。exit が先に決着してもタイマーが生きているぶんプロセスが終われず、ユニットテスト全体が10秒待たされていた（中身は1.2秒）。`clearTimeout` する `raceTimeout()` に集約した

- **stale マーカーの掃除が無関係なファイルを消せる状態だった**。`.nemo-run` が symlink（例: `.nemo-run -> .`）なら、`package.json` や `extensions.lock.json` が「不正なマーカー」として削除される。マーカー置き場を `lstat` して**通常のディレクトリでなければ検証ごと失敗**させ、対象を `<pid>.json` の**通常ファイル**に限定し、削除は**ファイル名の PID が死んでいるときだけ**にした
- **SIGKILL 後も終了を確認せずに進んでいた**。3秒待って諦めたあと後片付けに入るので「確実に死んでいる」保証になっていなかった。確認できなければ投げて、**一時ディレクトリを消さずに場所を表示する**ようにした
- **検証ハーネス自体にテストを置いた**（`scripts/harness.test.mjs`）。本体より先にハーネスのほうが危険な操作（再帰削除・プロセス停止・lock の書き換え）を持っていたのに、テストが無かった

- **起動中 Nemo の検出を `ps` からマーカーファイルに変更**。`electron-vite dev` は `Electron .` として起動するのでコマンドラインに `out/main/index.js` が出ず、検出をすり抜けて `verify:ext-update` が実行できてしまった。アプリ自身が `.nemo-run/<pid>.json` を書き、検証側は生存 PID を見て stale を掃除する方式にした（`ps` は補助）
- **パス封じ込めを字句比較から symlink 検査つきに変更**。`extensions/<正しい形式の id>` が外部ディレクトリへの symlink なら、`path.resolve` 後の比較は通り抜けたうえで `readdir` がリンク先を列挙し、再帰削除で外を消せた。`safeJoin()` が base を realpath したうえで base から下の各段を `lstat` する形にし、canary 付きの回帰テストを置いた（macOS の一時ディレクトリは `/var -> /private/var` を経由するので、**base より上の symlink は許容**しないと何も通らない点に注意）
- **子プロセスの停止を固定 sleep から exit 待ちに変更**（`stopChild()`）。SIGTERM 後 1.5 秒で次へ進んでいたため、同じ CDP ポートの再利用や、まだ使っている一時ディレクトリの削除と競合しうる状態だった

- **受け入れ基準 0-5 のうち3項目を Phase 1 に移管した**（未チェックのまま放置しない）:
  - `service worker を停止・再起動しても動く` → Phase 1-10。Electron に SW を止める API が無く、idle 停止を待つ検証は非決定的で、採用可否のゲートに載せられないため。起動し直せることと `chrome.storage.local` が残ることは自走検証済み
  - `⌘⌥I で DevTools が開く` → Phase 1-7。DevTools が開くこと自体は IPC 経由で検証済みで、残るのは「アクセラレータのキー入力が届くか」だけ。キーバインド全体を扱う工程に寄せた
  - `更新後に実 Vault で自動入力が動くか` → Phase 1 の確認。`chrome.storage` が引き継がれることは `verify:ext-update` で機械検証したので、残りは目視のみ
- **検証ハーネスが実リポジトリの拡張を差し替えていた**（`verify:ext-update` が userData だけ一時化して lock / extensions / cache は本物を使っていた）。稼働中の Nemo の拡張を巻き込んだので、**lock・extensions・cache まで一時領域に複製して完全に隔離**し、あわせて**Nemo が起動中なら検証系を実行拒否**するようにした
- **`mise run verify` が別プロセスを検証して PASS しうる状態だった**。固定ポート（9333 / 8787）を使い、`verify-spike` にエンドポイントを渡しておらず、起動したページサーバの早期終了も見ていなかった。実際に既存の 8787 サーバを検証して全 PASS した。**毎回空きポートを採番 → `NEMO_CDP` / `NEMO_TEST_PAGES` で明示的に伝播 → 子プロセスの生存と「自分が起動したサーバか」を確認**する形に直した
- **壊れた lock でリポジトリを再帰削除できる状態だった**（`id: ".."` なら削除対象がリポジトリルートになる）。拡張 ID / version / `unpackedRoot` / `source.url` を検証し、削除・展開のパスがすべて `path.resolve` 後に所定のディレクトリ配下であることを確認するようにした。検証は `src/shared/ext-lock.js` に置いて main プロセスとスクリプトで共有する（実装が二重にあったのが遠因）

- **拡張の完全性検証を「アーカイブの hash」から「展開後ツリーの hash」に変更**（レビュー指摘）。ロード前に照合し、不一致ならロードしない。あわせてロード後の ID / version 不一致では `removeExtension()` で必ず外す
- **ナビゲーションで許可する scheme を絞った**（レビュー指摘）。通常ページは `http:` / `https:` と `about:blank`（厳密一致）のみ。`chrome-extension://` はロード済み拡張の ID に一致する場合に拡張自身の経路でだけ許可し、`devtools:` は `loadURL` 経由では一切許可しない。拡張から渡される URL（`chrome.tabs.create` / `chrome.windows.create`）も同じ検証を通す
- **ログに URL のパス・クエリ・フラグメントを出さないようにした**（レビュー指摘）。`redactUrl()` で `scheme://host` まで落とす
- **許可判定を Electron 非依存の `src/shared/navigation-policy.js` に切り出し、`node --test` の回帰テストを置いた**。計画 1-0 の「許可外 scheme を拒否する回帰テスト」を Phase 0 の時点で満たしている
- **`.mise.toml` を Phase 1-1 から前倒しで導入した**。`mise run dev` で「拡張の照合 → テストページのサーバ → remote debugging つきで起動」まで一発にする。起動方法が分からず手動確認に入れない、という状態を解消するため。remote debugging は `NEMO_REMOTE_DEBUGGING_PORT` が明示されていて packaged でないときだけ開く

- **`electron-chrome-web-store` を依存から外した**。Web Store 経由のインストールは lock からの再現ができず、Nemo の「不変 artifact だけをロードする」方針と矛盾する。`installChromeWebStore` を呼ばない以上このパッケージは使い道が無いので、依存ツリーを正直に保つために削除した（`chrome.webstorePrivate` が要るなら Phase 1-8 で戻す）
- **`loadAllExtensions` を使わず自前ローダにした**。`loadAllExtensions` はディレクトリを走査して見つけたものを全部読むだけで、lock との照合ができない。lock を1件ずつ `session.extensions.loadExtension()` に渡す形にして、**ID / version の照合と allowlist を実装として保証**した
- **拡張のロールバックは「lock を git で戻して再 materialize」に決めた**。旧 artifact は `.ext-cache/` に残るのでネットワーク無しで戻せる。`--rollback` のような別コマンドは作らない（lock が唯一の真実であるほうが状態が減る）

- **本体 repo を private → public（GPL-3.0）に変更**。`electron-chrome-extensions` が GPL-3.0 であり、public な Release からバイナリを配布するとソース提供義務が発生するため。あわせて**配信 repo を分ける理由（ソースを private に保つ）が消えたので、repo を3つから2つに減らした**
- **シークレットウィンドウは拡張なしに確定**。Electron が incognito セッションへの拡張ロードに対応していないため。Chrome も既定でシークレット時に拡張を無効化するので、使い心地としては Chrome と同じになる
- **ダウンロード・セッション復元・権限ダイアログ・ページ内検索などを Phase 2 → Phase 1 に前倒し**。Phase 1 の完了条件「一日 Nemo だけで使える」と機能範囲が一致していなかったため
- **拡張のバージョン固定を「lock JSON + Web Store インストール」から「不変 artifact の直接ロード」に変更**。`installExtension` にバージョン指定がなく、lock からの復元ができないため。あわせて `autoUpdate: false` を明示
- **age のシークレット保管基盤を Phase 2 → Phase 3 に移動**。Phase 2 には利用者がおらず、最初の利用者（ベーシック認証の自動入力）が Phase 3 にあるため。常用移行までの距離が縮む
- **パッケージング工程を Phase 1-1 に明示的に追加**。`better-sqlite3` はネイティブモジュールで Electron の ABI 向け rebuild が必要、両拡張ライブラリは preload の同梱確認が必要、といった「開発起動では露見しない」問題があるため。clean build した `.app` での smoke test を完了条件に含めた
- **通常ナビゲーションの scheme allowlist を Phase 1-0 に追加**。popup と外部 protocol だけ制限しても、コマンドバーからの `javascript:` / `file:` やリダイレクト後の scheme が素通りするため
- **Phase 3 の広告ブロックから DNR の断定を削除**。Electron 公式の対応 API 一覧に `chrome.declarativeNetRequest` が無いことを確認したので、「スパイクで確認し、不可なら拡張に寄せる」に修正した
